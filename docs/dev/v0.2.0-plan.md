# claude-seo-ai v0.2.0 — "works on any site" upgrade plan

> Scope: one release (v0.2.0) in six phases. Each phase leaves the plugin working and tested. Items marked **TO-VERIFY** / **UNVERIFIED** must be checked against live docs/APIs before that code is written; nothing is committed or pushed unless the user asks.

## Context

`claude-seo-ai` (49 stars, 5 forks, 0 issues) is a skill-first Claude Code plugin: 4 command skills (`audit`/`geo`/`score`/`fix`), an orchestrator, ~21 `seo-*` audit modules (M1–M21), 5 subagents, and optional zero-dep Node scripts. Public criticism (social, not GitHub issues): **"can't go into Shopify or WordPress"**, **"can't work on an audit"**, **"can't compare URLs"**. The user's goal: make it work on *any* website (Shopify, WordPress, Next.js, Wix…), be a genuinely complete audit tool, and level up the GEO/AI-search side.

### Verified facts driving the design (checked 2026-09-05 in this session)

**Why "can't work on an audit" is plausible today**
- `seo-crawl-render` acquires URLs with `WebFetch` and promises `status_chain`, `headers`, `raw_html`. Claude Code's WebFetch **returns a small-model markdown summary, never raw HTML, headers, or status codes**, and refuses cross-host redirects (verified from the tool's own schema in this session). The prompt-level snapshot layer therefore cannot deliver what every module reads.
- The bundled scripts **do** fetch real HTML with Node `fetch` and work on live sites: probed Allbirds (Shopify), TechCrunch (WordPress VIP), Vercel (Next.js) — `parse-html`, `validate-jsonld`, `parse-robots-sitemap` all returned correct data. So the fix is to make the scripts the acquisition layer, not WebFetch.
- Nothing persists: no PageSnapshot on disk, no findings/report file, `score` relies on "the most recent audit this session", `fix` on "the last audit". No multi-page crawl exists despite `scoring-model.md` promising a site-level rollup.
- Dead reference: `schema/jsonld-templates/` is cited by `references/schema-tier1.md` and `skills/seo-schema-jsonld` but does not exist (`schema/` has only the two JSON Schemas).
- Skills use `allowed-tools: … Task` (the subagent tool is now `Agent`). **Env-var correction (verified by inspecting the installed Claude Code 2.1.261 binary):** `${CLAUDE_SKILL_DIR}` *is* substituted into skill bodies and `allowed-tools` at load time (resolves to the skill's own directory), so the 14 skills using `${CLAUDE_SKILL_DIR}/../../scripts/x.mjs` produce a valid absolute path when the skill is loaded; the **bare `node scripts/x.mjs`** forms (3 skills, 2 agents, `score`) are the broken ones (cwd = user project). Agents are not skills, so agent prompts must receive the resolved scripts path from the orchestrator instead of relying on any `${…}` token. `${CLAUDE_PLUGIN_DATA}` is substituted in plugin skill/agent content and hook/MCP configs (per the official plugins reference) but is **not guaranteed as an environment variable** inside the Bash commands the model runs → persistence needs a fallback (`--out` → `$CLAUDE_PLUGIN_DATA` if set → `~/.claude-seo-ai/`). On disk the data dir pattern is `~/.claude/plugins/data/<marketplace>-<plugin>/` (here `claude-seo-ai-claude-seo-ai/`, currently empty), so when a skill runs a script via Bash it should pass the resolved dir explicitly (`--out "${CLAUDE_PLUGIN_DATA:-$HOME/.claude-seo-ai}"`). Skill frontmatter fields confirmed in this build: `user-invocable` (default true), `disable-model-invocation`, `argument-hint`, `allowed-tools`, `model` (incl. `inherit`), `effort`, `hooks`, `paths`, `context`, `whenToUse`. Plugin manifest supports explicit `skills:`/`agents:` path lists and `${CLAUDE_PLUGIN_ROOT}/bin/…` entries.
- Sitemap parser leaves XML entities undecoded in `<loc>` (`&amp;` seen in Allbirds sample URLs).

**Why "can't go into Shopify/WordPress" is true today**
- Vertical detection exists (ecommerce/blog/saas/docs/local) but there is **no platform/CMS/framework detection** and no platform-specific findings or fix paths. `fix` assumes local files and "locates the exact insertion point" with no route→file mapping for any framework and no adapter for hosted CMSs.
- Detection signals verified live: Shopify → `cdn.shopify.com`, `Shopify.theme`, `/cdn/shop/`; WordPress → `x-powered-by: WordPress VIP`, `link: </wp-json/>; rel="https://api.w.org/"`, `/wp-content/`; Next.js → `x-powered-by: Next.js`, `/_next/`.

### Claude Code mechanics (research agent, official docs at code.claude.com/docs, 2026-09-05)
- Env placeholders documented: `${CLAUDE_PLUGIN_ROOT}` (install dir, wiped on update), `${CLAUDE_PLUGIN_DATA}` (`~/.claude/plugins/data/{id}/`, persistent, created on first reference; id = `<plugin>-<marketplace>` with non `[A-Za-z0-9_-]` → `-`), `${CLAUDE_SKILL_DIR}` (the skill's own dir), `${CLAUDE_PROJECT_DIR}`, `${CLAUDE_SESSION_ID}`, `${CLAUDE_EFFORT}`. Substituted **anywhere in skill and agent content**, in hook/monitor commands, MCP `command/args/env`. Open GitHub issues report `CLAUDE_PLUGIN_ROOT` sometimes unset in hooks → scripts need a defensive fallback (`${CLAUDE_PLUGIN_ROOT:-$(dirname "$0")/..}` style / the skill passes an absolute path).
- Subagent tool is `Agent` (`Task` survives only as an alias since v2.1.63). Permission syntax `Agent(<name>)`.
- Skill frontmatter: `name`, `description`, `when_to_use`, `argument-hint`, `arguments`, `disable-model-invocation` (also blocks preloading into subagents), `user-invocable` (false hides from `/` menu), `allowed-tools`/`disallowed-tools`, `model`, `effort`, `context: fork` + `agent` + `background`, `hooks`, `paths`, `shell`, `metadata`. Dynamic context injection: `` !`cmd` `` runs before Claude sees the skill (no permission prompt; exit ≥2 fails). Only `name/description/license/compatibility/metadata/allowed-tools` are portable to claude.ai packaging.
- Agent frontmatter: `name`, `description`, `tools`, `disallowedTools`, `model` (`inherit` ok), `permissionMode`, `maxTurns`, **`skills` (preloaded at startup)**, `mcpServers`, `hooks`, `memory`, `background`, `effort`, **`isolation: worktree`**, `color`.
- `plugin.json` supports `userConfig` (typed prompts at enable time; `sensitive: true` stores in secure storage; exposed as `${user_config.KEY}` in MCP/hook configs and `CLAUDE_PLUGIN_OPTION_<KEY>` env vars) — the sanctioned way to collect a Shopify Admin token, WP application password, PSI key. Plugins may ship `.mcp.json` at plugin root and a `bin/` dir added to Bash PATH (not for claude.ai org distribution). Hook events include `PostToolUse` (verify after writes), `SubagentStart/Stop`, `FileChanged`.
- `/plugin` shows a **context-cost estimate** and a Stats tab before install → keep the always-on footprint small (module skills hidden + preloaded per agent).
- WebFetch: lossy by design ("Claude receives the model's extracted answer, not the raw page"), 15-min cache (`CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS`), cross-host redirects returned not followed, no headers/status. Reproduced live.

### Script-layer defects (exploration agent 2; `node tests/run.mjs` = 30 passed / 0 failed on Node 24)
23. `util.mjs emit()` calls `process.exit` → scripts are not importable as modules and large stdout can truncate on pipes. Every script runs at import time (top-level await). A runner/crawler must `execFile` them or `emit` must be refactored to return.
24. Regex attribute extraction requires quotes and uses `[^"']*` → **apostrophes truncate values** (`content="Don't miss"` → `Don`), unquoted attributes never match, `\bsrc=` also matches `data-src=`, `width="100%"` counts as sized. No `<base href>`, no `rel` capture (nofollow/sponsored invisible), only first canonical returned (multiple-canonical undetectable), no `Link:` header canonical/hreflang, `<script>/<style>` not stripped before headings/links in `parse-html`, only 6 HTML entities decoded, JSON-LD `type="application/ld+json; charset=…"` missed, no microdata.
25. `fetchText`: `redirect:'follow'` (no chain), sends only `user-agent`, no `Accept*`, no gzip/binary handling (`.xml.gz` → garbage), no size cap, no retries. `loadInput --file` fakes `status: 200`, empty headers.
26. `parse-robots-sitemap`: detects sitemap index but never recurses; no gzip; fetches only first declared sitemap and only with `--url`; `lastmod` counted not extracted; `may_block_render_assets` scans all UA groups; robots 5xx → exit 1 instead of "disallow all"; `new URL()` throws unguarded on scheme-less input; missing `Amazonbot`/`Claude-Web` vs `references/ai-crawlers.md`; ignores `Content-Signal`, `Host`, `Clean-param`.
27. `link-graph`: `www` vs apex = external; fragment links count as internal self-links; serial crawl with no robots respect, no depth, no status capture; redirect key mismatch → phantom orphans; `total_links` means different things in two scripts.
28. `psi-client`: never checks `origin_fallback` → origin-level CrUX presented as page-level; exit 0 on API failure vs 1 on missing arg; no retry/backoff.
29. `score.mjs`: gating ignores `expected_impact.confidence` (spec says speculative never caps); gating is axis-only; pre-cap value discarded; `totalW===0` → 0/F instead of "unscored"; unknown module/status silently dropped, no schema validation; conditional categories activate on "≥1 finding" not on detected vertical; `interpret()` pairs the wrong sentence with the AI score; cap branch never exercised by tests.
30. `validate-jsonld`: 14 types, no `SoftwareApplication`, no LocalBusiness subtypes, key-presence only (empty/null passes), no enum/URL/date validation, `--type` filter partial.
31. Heuristics (`check-answerblocks`, `factdensity`, `check-freshness`) are **English-only** (Spanish pages read as zeros = silent pass); boilerplate strip removes `<header>` inside `<article>` (kills H1); passages are `<p>/<li>` only (div-based Shopify/Webflow/Squarespace markup → 0 passages); bare pronouns count as anaphora; numeric density counts years/prices; authority-host regex matches inside paths; freshness `schema_vs_lastmodified_mismatch` false-positive on non-ISO dates; first-wins on conflicting dates.
32. Tests: single well-formed fixture; no sitemap XML fixture; no `--url`/`--crawl`/`--deep`/`--type`/stdin tests; no exit-code or schema assertions; no `.github/` CI. Windows: `package.json check` is a POSIX loop; `guard-write` patterns are `/`-only. Vercel-skills install (`npx skills add`) ships only `SKILL.md` files → every `verification.reproduce` is broken under that channel.

## Recommended approach — v0.2.0 in six phases

Guiding principle: keep the skill-first architecture and the honesty guardrails, but move **acquisition, crawling, scoring, comparison and platform detection into deterministic zero-dep scripts**, make the skills consume their JSON, and make `fix` platform-aware. Each phase leaves the plugin working; run `node tests/run.mjs` after every phase.

### Phase 0 — Make the existing audit actually run (wiring fixes, no new features)
