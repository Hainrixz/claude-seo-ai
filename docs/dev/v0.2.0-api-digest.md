### API
scripts/lib/util.mjs (all legacy exports unchanged in signature: fetchText, loadInput, stripTags, decodeEntities, getTitle, getMetaName, getMetaProperty, getLinkRel, getHtmlLang, getCharset, getHeadings, getImages, getLinks, getJsonLd, isBcp47) plus:
- `EXIT` frozen {OK:0, USAGE:1, RUNTIME:2, THRESHOLD:3}. Semantics: 1 = bad invocation (missing/invalid args, unreadable input path), 2 = ran but failed (network, thrown error), 3 = gate not met (check.mjs failures, future audit --fail-under).
- `parseArgs(argv = process.argv.slice(2))` -> {_:[...positionals], ...flags}. `--k v`, `--k` (=> true when next is missing or starts with --), `--k=v` (split at first =), `--no-k` (=> k:false, consumes nothing), repeated `--k a --k b` (=> ['a','b']; first occurrence stays scalar), `--` terminator (rest -> _). Single-dash tokens are positionals (legacy).
- `emit(obj, code=0)` -> writes JSON.stringify(obj,null,2)+'\n' to stdout, sets process.exitCode=code (non-integer -> 2), RETURNS obj. Never exits.
- `isMain(metaUrl)` -> boolean; realpathSync(process.argv[1]) === realpathSync(fileURLToPath(metaUrl)) (case-insensitive on win32); never throws (false on any error/undefined). NOTE: inside a node:test child the test file itself is main.
- `runCli(main, argv?)` -> awaits main(parseArgs(argv)); if it returns {result, code} emits result with code (default 0); a bare object is emitted with code 0; a throw emits {error: message[, stack when CLAUDE_SEO_AI_DEBUG is set]} with code 2.
- `inputFailure(input)` -> null when input usable, else {result:{error}, code} with source 'none'|'file' -> USAGE(1), 'url' -> RUNTIME(2).
- `loadInput(args)` -> {source:'file'|'url'|'none', html, headers, status, finalUrl?, error}; --file now reports status:null and headers:{} (never a fabricated 200).

Every CLI script (parse-html, validate-jsonld, parse-robots-sitemap, check-answerblocks, factdensity, check-freshness, hreflang-check, link-graph, psi-client, score, check): `export async function main(args) -> { result, code }` + `if (isMain(import.meta.url)) runCli(main);` at the bottom; zero side effects on import; no process.exit anywhere except scripts/guard-write.mjs (untouched). Output keys/order identical to v0.1.0. Extra named exports for reuse: validate-jsonld `SPEC`; parse-robots-sitemap `AI_BOTS, parseRobots(text), aiPosture(robots), parseSitemap(xml)`; score `SEARCH, AI, band(v), computeScore(categories, findings, axis), scoreFindings(parsedArrayOrObject)` (pure, no I/O); psi-client `THRESH`; hreflang-check `extractHreflang(html)`; link-graph `classify(links, baseUrl)`; check `lintSkillMarkdown(text, {dirName})`.
Behavior deltas: validate-jsonld `--type` may repeat (array) and a bare `--type` is ignored; parse-robots-sitemap returns USAGE(1) for a scheme-less --url instead of throwing, fetch failures -> RUNTIME(2); link-graph --crawl validates the base URL (USAGE) and orphan detection now excludes the real start URL; score: TTY with no --findings or empty stdin -> USAGE(1) {error, hint} instead of hanging/cryptic JSON error; psi-client: missing --url -> {status:'needs_api', error:'provide --url'} exit 1; API failure -> exit 0 with status 'needs_api' plus `api_error: {kind:'http'|'network'|'non_json', status:number|null, detail:string}` alongside legacy error/detail/hint — callers MUST branch on `status`, not the exit code.

scripts/check.mjs: `node scripts/check.mjs [--root <repo>] [--concurrency 8]` -> JSON {ok, root, syntax:{checked, errors:[{file,error}]}, json:{checked, errors:[]}, versions:{plugin, marketplace, package, aligned}, skills:{checked, warnings:[{skill, message}]}, summary}. Walks scripts/**/*.mjs + tests/**/*.mjs (skips fixtures/, snapshots/, node_modules) with `node --check`; parses .claude-plugin/plugin.json, .claude-plugin/marketplace.json (plugins[] entry named claude-seo-ai), scripts/package.json, hooks/hooks.json, schema/*.json; skill lint warns on: no leading ---, unclosed frontmatter, missing name/description, name != directory, `Task` in allowed-tools, bare `node scripts/` in the body (line-numbered). Exit 0 when ok (warnings allowed), 3 (EXIT.THRESHOLD) on syntax/JSON errors or version mismatch. scripts/package.json: "test": "node ../tests/run.mjs", "check": "node check.mjs".

tests/run.mjs: discovers tests/unit/*.test.mjs and tests/e2e/*.test.mjs (readdirSync, sorted; no glob), runs them through node:test `run({files, concurrency})` (one child per file, so a test file that dies cannot kill the runner), prints `<file>` headers + `  ok/FAIL/skip <name>` lines (failure message excerpt inline), forwards child stdout/stderr, then `N passed, M failed[, K skipped] (T tests, F files)`; process.exitCode = 1 on any failure or when zero tests ran. ### Open issues
- Token kind 'raw' is a seventh kind beyond the six named in the task (open/close/self/comment/doctype/text): raw-text elements are emitted as ONE token with .content and no separate close token, so consumers gathering text must treat text tokens only (raw content never leaks). Documented at the top of html.mjs.
- parseDocument does not emit cookie_names[] (plan 1b lists it) — cookies come from response headers, not HTML; the snapshot/fetch layer should derive names from set-cookie. Everything else in the 1b list is present.
- Landmark regions come from tags and ARIA roles only; class/id heuristics (e.g. <div class="site-footer">) are deliberately not used, so pages with no semantic landmarks report region 'body' everywhere and word_count covers the whole body. A <footer> nested inside <article> (author byline) is treated as boilerplate per the plan's rule.
- Anchors with anchor_source 'image-alt'/'aria-label'/'title' fill `anchor` when there is no visible text; parse-html links.generic_anchors therefore sees alt text — a small behavior delta vs v0.1.0 only on image links (blog-post fixture unaffected).
- validate-jsonld types_present now includes nested types (e.g. Person from Article.author); any downstream consumer that assumed only root types should be aware. tests/e2e/cli-exit-codes.test.mjs (owned by another stage) was edited minimally for this.

The Playwright headless shell exits cleanly. If a future Chrome changes stdout buffering, the hard timeout (max(30 s, 2×--timeout)) is the fallback and yields confidence 'reduced'.
- hostKey keeps 'www.' (spec: lower-cased host, ':'→'_'), so www.example.com and example.com are separate hosts on disk; resolveRunRef('latest:<host>') falls back to a www-insensitive match. Phase 5 compare should decide whether to canonicalize (lib/urlnorm hostKey strips www — different semantics, kept separate on purpose).
- --snapshot support arrived automatically only for loadInput-based scripts; parse-robots-sitemap.mjs and psi-client.mjs take --url directly and still need wiring by their owners (use readSnapshot(args) → snapshot.target.final_url and <run_dir>/site/robots.json).
- needsRender treats framework markers (next_data, nuxt, reactroot, angular, sveltekit, remix) as a render signal only when word_count < 400, so text-rich SSR pages are not flagged; the markers are still reported in render.markers. Tune FRAMEWORK_WORD_THRESHOLD if the M4 checks want stricter behaviour.
- Retention for gap runs relies on keepFor(host_key) matching keys that start with '_gap' (or an explicit --keep 5); compare.mjs must store gap runs under '_gap/…' hosts or pass --keep.
- Same-second run ids get a '-2', '-3' suffix (RUN_ID_RE tolerates it); crawler callers should open one run via openRun() and pass it as opts.run to snapshotUrl() rather than relying on timestamps.
- Sitemap files are fetched with a 50 MB + 4 KB cap so over_50mb can be reported; a site with many huge sitemaps will cost memory/time up to --sitemap-max files.
- Windows paths: setLatest uses a junction for 'latest' and everything else is path.join-based, but nothing was executed on Windows in this session.
- The tests/unit/lang.test.mjs failure seen mid-session belonged to another agent's untracked in-progress files and was green in the final full run (390/390).
